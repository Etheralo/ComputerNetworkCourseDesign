## 2. TCP 服务端：socket_demo/server.py

### 2.1 导入和 main 参数解析

`argparse` 解析命令行，`socket` 调用操作系统网络接口。`--host` 是本机监听地址，默认 `127.0.0.1`；`--port` 默认 `9000`；`--once` 表示处理一个客户端后退出。

跨设备演示可在服务端运行：

```bash
python -m src.socket_demo.server --host 0.0.0.0 --port 9000
```

`0.0.0.0` 监听所有本机 IPv4 接口，不是客户端的连接目标。防火墙和网络隔离仍可能阻止访问。

### 2.2 创建、绑定、监听

`socket(AF_INET, SOCK_STREAM)` 创建 IPv4 TCP Socket；`SO_REUSEADDR` 有助于重启时重新绑定；`bind()` 绑定本机 IP/端口；`listen()` 进入监听状态。这些调用使用操作系统的 TCP 实现，不是 Python 代码自己实现握手或重传。

### 2.3 accept 循环

`accept()` 阻塞等待，返回专用于当前客户端的 `connection`，以及客户端地址 `client`。监听 Socket 与通信 Socket 不同：前者继续持有监听端口，后者负责一段会话。

`serve_connection()` 是同步调用，因此当前会话结束后才处理下一客户端。没有 TCP 多客户端线程池。`--once` 控制会话结束后是否跳出监听循环。

### 2.4 serve_connection：包装网络流和读取

`connection.makefile("rwb")` 提供带缓冲的二进制文件接口，方便按行读写，不创建磁盘文件。循环内的 `readline(65537)` 读取到换行、EOF 或长度上限。

TCP 是连续字节流，不保留一次 write 的消息边界；本协议约定每条消息以 `\n` 结束。即使多条消息一次到达，也可以逐行读取。正常消息上限为含换行的 65536 字节，多读一个字节用于判定超长。

### 2.5 EOF、长度和编码检查

`not raw_line` 表示 EOF，结束会话；空消息会收到 `b"\n"`，不是 EOF。超过上限或读取结果没有换行，返回错误并关闭会话。没有设置服务端读取超时，因此一条未结束且未达到上限的消息仍可能一直等待。

`rstrip(b"\r\n")` 去掉行尾换行，再用 UTF-8 解码；非法编码返回错误。长度按字节而非汉字数计算。

### 2.6 exit 与 ACK

`message.strip().lower() == "exit"` 忽略前后空白和大小写，命中后回复 `BYE\n`，刷新缓冲并返回。普通消息回复 `ACK: 原消息\n`，随后继续循环。

这里的 ACK 是应用层文本，不是 TCP ACK。每次 write 后的 `flush()` 将缓冲数据交给底层 Socket，不保证对方已经处理。函数返回后，with 关闭通信资源，但不会关闭 main 中的监听 Socket。

## 3. TCP 客户端：socket_demo/client.py

### 3.1 main 与输入模式

`--host` 是服务端实际地址，`--port` 是服务端监听端口。可重复的 `--message` 通过 `action="append"` 汇集成列表；不传时为 None，进入交互模式。

例如另一设备连接服务端 `192.168.1.100`：

```bash
python -m src.socket_demo.client --host 192.168.1.100 --port 9000
```

无需指定客户端本地端口，操作系统通常会选择出口地址和临时端口。

### 3.2 exchange：连接与资源管理

`create_connection(..., timeout=5)` 建立 TCP 连接，并设置 Socket 超时。5 秒也影响后续阻塞网络操作，但不限制用户键盘输入时间。嵌套 with 管理连接和缓冲文件对象，连接在收发循环外创建，所以多条消息复用同一连接。

### 3.3 获取下一条消息

交互模式使用 `input()`，遇到输入结束 EOFError 时发送 exit。脚本模式用迭代器逐条取消息，列表耗尽 StopIteration 时自动发送 exit。

### 3.4 发送与等待响应

正文加换行后编码为 UTF-8，write 后 flush，再用 readline 等待一条回复。没有回复而读到 EOF 时抛出 ConnectionError；收到回复后解码显示。发送的是 exit 时才返回，否则继续下一轮。

这是同步请求—响应，不是双方可以随时主动发言的聊天系统。正文中的换行会变成额外消息边界，当前协议不是任意多行文本或二进制文件协议。

## 4. 本地表：dns_relay/local_table.py

### 4.1 LocalTable 数据容器

`records` 是域名到 IPv4 字符串的字典。dataclass 自动生成初始化等方法；frozen 禁止重新给属性赋值，但不冻结字典内部内容。

### 4.2 load：读取和清洗

使用 Path 以 UTF-8 读取文件，按行遍历并保留行号。截去 `#` 后的注释，去掉空白，跳过空行。剩余部分必须恰好有两列：`IPv4 domain`，否则报带文件路径、行号的错误。

### 4.3 load：校验和存储

`ipaddress.ip_address()` 检查地址，额外拒绝 IPv6。规范化域名后存入字典，同域名重复配置以后面的为准。启动时加载一次，后续查询不重读文件；修改配置需重启。

### 4.4 normalize_domain 与 lookup

规范化去掉末尾点并转小写，因此 `LOCAL.Test.` 能匹配 `local.test`。lookup 返回 IPv4 字符串或 None；`0.0.0.0` 是已命中的屏蔽标记，不能与未命中混淆。屏蔽响应由 Relay 决定，不由查表函数发送。

## 5. DNS 编解码：dns_relay/dns_codec.py

### 5.1 常量与 DnsFormatError

头长 12 字节，A 类型值 1，IN 类别值 1。基础响应码：0 为 NOERROR，1 为 FORMERR，2 为 SERVFAIL，3 为 NXDOMAIN。解析遇到不合法或不支持的结构时抛出 DnsFormatError，让上层决定如何回包。

### 5.2 DnsHeader 与二进制头部

六个字段依次为 ID、FLAGS、QDCOUNT、ANCOUNT、NSCOUNT、ARCOUNT。`from_bytes()` 先校验长度，再用 `struct.unpack("!6H", ...)` 读六个 16 位整数。`to_bytes()` 逆向打包。

`!` 表示网络大端序；H 为 16 位无符号整数。报文字段必须按协议顺序和长度处理，不能直接发送整数的十进制文本。

### 5.3 DnsQuestion 与 DnsQuery

Question 保存域名、类型、类别、原始问题字节 wire，以及结束偏移 end_offset。Query 组合 Header、Question 和完整原始 packet。原始字节用于保持转发内容，结束偏移用于读取后续记录。

### 5.4 encode_name：将域名变成标签序列

先去尾点，根域输出一个零字节。普通域名按点拆分，每段 ASCII 编码后写入长度和内容，末尾写零；每段要求 1～63 字节，整体编码不超过 255 字节。

例如 `local.test` 对应 `05 local 04 test 00`，其中 05/04/00 是字节值，不是字符文本。本函数不自动进行 IDNA 转换，国际化名称需先转为 punycode。

### 5.5 decode_name：普通标签与压缩指针

初始化 labels、当前位置 position、返回偏移 next_offset、已访问指针集合和跳转计数。逐轮先检查读位置是否在包内。

若标签首字节高两位为 11，则后续两字节组合成一个 14 位偏移，跳到报文其他位置读取名称；检查越界、重复目标和最多跳转次数，防止循环。第一次遇到指针时保存其后两个字节的位置作为 next_offset。

若为普通标签，读取长度及内容，校验边界和 ASCII，并累计解压长度。零长度标签表示名称结束。其他高位形式不支持。

最终返回 `(域名, 原始名称字段结束偏移)`。压缩指针追踪位置不等于后续 QTYPE 的位置，这是区分 position 与 next_offset 的原因。

### 5.6 parse_question 与 parse_query

parse_question 解码 QNAME，再读取各 2 字节的 QTYPE/QCLASS，保留原始问题字节。parse_query 解析 Header，要求问题数量为 1，再组装 DnsQuery。它没有完整验证所有报文区段，QR 查询标志由 Relay 再检查。

### 5.7 _response_flags：组装响应标志

| 位掩码 | 功能 |
| --- | --- |
| `0x8000` | 设置 QR=1，表示响应 |
| `0x7800` | 从原请求保留 OPCODE |
| `0x0100` | 从原请求保留 RD，即请求递归标志 |
| `0x0080` | 设置 RA，声明递归服务可用 |
| 最低 4 位 | 基础 RCODE |

本地响应不设置 AA 权威标志。RA 不表示本程序自己从根服务器逐级解析，而是可使用上游服务。

### 5.8 build_local_a_response：本地 IPv4 回答

先将 IPv4 转为四字节，构造保留原 ID 的响应头：QD=1、AN=1、NS=0、AR=0。Answer 依次为名称、类型、类别、TTL、RDLENGTH、RDATA。

名称用 `0xC00C` 指向偏移 12 的 Question 名称；类型 A、类别 IN、默认 TTL 60 秒、RDATA 长度 4。最后拼接响应头、原问题和回答。设置 TTL 不等于 Relay 已实现缓存。

### 5.9 build_error_response：尽可能保留请求信息

短包有两个字节就提取 ID，有四个字节就提取原标志；完整且可解析的单问题才复制 Question。解析失败时允许返回 QD=0，所有错误响应 AN=0。

该函数被用于 FORMERR、NXDOMAIN 和 SERVFAIL。复制 Question 的实现不是针对任意外部压缩引用重新编码，不能将其描述为完整通用的 DNS 重写器。

### 5.10 build_query 与 response_code

build_query 构造 RD=1、QD=1 的请求，拼接编码后的域名以及类型/类别。response_code 用 `flags & 0x000F` 提取基础返回码，不处理 EDNS 扩展 RCODE。

### 5.11 parse_a_answers：展示回答

跳过 Question 区，按 ANCOUNT 遍历 Answer。解码每条 NAME，再读取 10 字节固定字段及变长 RDATA，检查截断。只将 A/IN 且长度为 4 的数据转成 IPv4 字符串，其余记录按长度跳过。

此函数不提取 AAAA，也不遍历权威区和附加区；空列表不必然代表域名不存在。

## 6. DNS Relay：dns_relay/server.py

### 6.1 导入、日志与异常

相对导入适配 `python -m`；备用导入支持直接运行文件。logging 输出请求信息，QUERY_TYPE_NAMES 将类型数值变成可读名称。UpstreamError 用于将转发内部捕获到的错误传给 resolve。

### 6.2 __init__：配置、并发与监听

检查工作线程数量至少为 1，解析上游地址，阻止部分明显的上游指回自身配置；这不是完整网络环路检测。保存表、超时、最大包大小和日志器。

Event 用于停止信号；ThreadPoolExecutor 限制同时工作的线程数；BoundedSemaphore 将运行中加排队中的任务限制为 workers 的四倍。创建 IPv4 UDP Socket、绑定本机地址，设置 0.2 秒接收超时以定期检查退出。

### 6.3 address：查询实际绑定地址

getsockname 返回真实地址。测试和演示传入端口 0 时，系统自动分配端口，调用此属性取得实际值。

### 6.4 serve_forever：接包与分派

记录启动信息后循环 recvfrom。超时继续检查停止条件，关闭引起的错误在停止状态下退出，否则继续向上抛出。

信号量尝试获取失败表示过载，立即返回 SERVFAIL。成功则提交 `_handle_request` 到线程池，并注册任务完成回调归还名额。退出循环时取消排队任务并等待已开始任务收尾。

### 6.5 shutdown：请求停止

设置 Event 并关闭监听 Socket。若服务运行在后台线程，调用者还要 join 等待线程；线程池在 serve_forever 的 finally 中收尾。

### 6.6 resolve：核心三个分支

先解析请求，拒绝 QR=1 的响应包；解析失败返回 FORMERR 和日志分支名。

仅 OPCODE=0、QTYPE=A、QCLASS=IN 时查本地表。`0.0.0.0` 返回 NXDOMAIN，普通 IPv4 返回本地 A。其他情况调用 _forward；捕获 UpstreamError 时返回 SERVFAIL。函数返回 `(响应字节, 分支名称)`，发送由调用方完成。

因此，blocked.test 的 AAAA 查询会转发，而不是本地屏蔽。不能声称当前屏蔽覆盖所有查询类型。

### 6.7 _forward：独立 Socket 和总超时

以 monotonic 计算截止时间，每个请求创建独立 UDP Socket。UDP connect 指定对端和接收来源，不执行 TCP 握手；原查询原样发送。

循环计算剩余时间并设置接收超时，检查返回头部 ID 和 QR。错误 ID 或 QR 继续等待，但不重置截止时间；合格响应原样返回。

当前只检查来源、头部 ID 和 QR，并未完整比较 Question 或解析全部响应；没有重传、缓存和 UDP 截断后的 TCP 回退。不同请求使用独立 Socket 隔离，不靠全局 ID 重写表。

内部 try 捕获 OSError 和 DnsFormatError 后包装为 UpstreamError；但 Socket 创建和 connect 在该 try 外，它们自身的异常不会被这段逻辑转换为 SERVFAIL。这是现有边界，本次注释工作未修改它。

### 6.8 _handle_request：处理与观测

记录开始时间，尽量解析 ID、域名、类型作为日志字段；解析失败用占位值，仍交 resolve 生成响应。之后调用 _safe_send，计算毫秒耗时，记录客户端、ID、域名、类型、处理分支、上游和 RCODE。

日志帮助区分 local-a 与 upstream，因为两者都可能返回 RCODE=0。发送日志不等于客户端一定收到 UDP 报文。

### 6.9 _safe_send、参数与 main

_safe_send 用监听 Socket 的 sendto 回复原客户端；非关闭期间发送失败记录异常。

参数默认：监听 `127.0.0.1:5353`，上游 `8.8.8.8:53`，表 `config/dnsrelay.txt`，上游超时 2 秒，16 个工作线程。verbose 切换日志级别。main 配置日志、加载表、创建 Relay 并运行，处理 Ctrl+C 后清理。

## 7. 查询工具：dns_relay/query.py

### 7.1 QUERY_TYPES 与 query_relay

映射 A、NS、CNAME、MX、AAAA 到数值，统一用户类型大小写。未提供事务 ID 时从 0～65535 随机生成。构造请求，创建 UDP Socket，设置超时并发包，等待一次响应。

解析返回头部并校验 ID，不匹配抛出 DnsFormatError。该简易客户端未验证 recvfrom 返回的源地址，也没有重试；不要与 Relay 的已连接上游 Socket 混淆。

### 7.2 main 参数与输出

默认访问 `127.0.0.1:5353`，name 必填，type 默认 A，timeout 默认 3 秒；id 支持 `0x1234` 等写法。执行查询后显示 ID、QR、RD、RA、RCODE、QD、AN；A 查询另外显示 answers，其他类型不解码记录内容。

RCODE=0 仅表示无错误，不保证回答非空；AN=0 也不一定是 NXDOMAIN，必须结合 RCODE 和查询类型理解。

## 8. 离线演示：dns_relay/demo.py

### 8.1 DemoUpstream 生命周期

构造函数创建回环 UDP Socket，默认端口 0，保存实际地址并建立停止信号与后台线程。start 启动线程；run 循环接收演示请求，解析后固定返回 `203.0.113.9`；close 设置停止状态、关闭 Socket 并限时 join。

它是演示用伪上游，不提供真实公网解析，也不用于证明所有记录类型的应答正确性。

### 8.2 request

创建临时 UDP 客户端，设置 1 秒超时，发送给指定 Relay 地址，返回原始响应。解析和显示交给 main。

### 8.3 main

解析两个端口参数，拒绝相同非零端口；启动伪上游，创建真实 Relay 并用后台线程运行。依次查询 local.test、blocked.test、public.example，分别展示本地 IPv4、NXDOMAIN、上游固定 IPv4。

进入演示 try 后，无论查询成功或异常，finally 都会关闭 Relay、等待线程并关闭伪上游。服务启动阶段在 try 之前，并非所有初始化失败都由该 finally 覆盖。

### 9.3 test_socket_demo.py：1 项

socketpair 提供两个本机互连 Socket，后台运行 serve_connection；另一端一次写入中文、英文、exit 三行，按顺序断言两个 ACK 和一个 BYE，并检查线程结束。

它验证会话处理和分帧，不覆盖客户端 exchange、监听 accept、真实 IPv4 TCP 握手或跨设备防火墙。

### 9.4 test_dns_relay.py：10 项与辅助代码

FakeUpstream 记录收到的原始字节，返回固定 `198.51.100.7`，可故意替换事务 ID。它的 start/_run/close 管理后台接收线程和生命周期。集成测试 setUp 启动独立 Relay 和伪上游，tearDown 释放资源，query 通过真实回环 UDP 发送请求。

八个集成用例依次验证本地命中不上游、屏蔽返回 NXDOMAIN、未知域名原样转发、AAAA 转发、非标准 OPCODE 转发、短包 FORMERR、大小写匹配，以及 20 个不同 ID 请求的并发对应关系。

两个失败用例验证不可用上游和错误 ID 最终返回 SERVFAIL。不可用端口可能产生连接拒绝而非等待完整超时；AAAA 用例只断言请求转发，不断言伪上游的回答是合法 AAAA 记录。不同 ID 的并发测试也不等于专门覆盖了多个客户端使用相同 ID 的场景。

## 10. 答辩时应准确描述的边界

- TCP 是单客户端会话顺序处理；DNS Relay 才使用线程池并发。
- TCP 使用 UTF-8 换行协议，没有加密、身份认证或服务端会话读取超时。
- 本地 DNS 仅覆盖标准 A/IN 查询；屏蔽值不是覆盖所有类型的过滤器。
- DNS 编解码仅实现本项目需要的协议子集，不是完整 DNS 库。
- Relay 没有动态缓存、完整递归解析算法、DNS over TCP 或热加载。
- 自动化本机测试、伪上游演示和真实跨设备通信是不同层次的证据。

运行测试的命令为 `python -m unittest discover -s tests -v`，离线演示为 `python -m src.dns_relay.demo`，均在项目根目录执行。实际 Python 命令名称按本机安装调整。
